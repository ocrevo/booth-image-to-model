# Baseline of the current engine

The recorded numbers of the engine as it was before the honest-fit changes (I1), measured with this harness on the synthetic
`oracle-v1` suite. Later versions are compared with these numbers (`compare_results.py`), scene by scene.

> **Harness 1.1 note (2026-10-19).** The tables below were regenerated by rescoring the stored raw outputs of the baseline run with
> harness 1.1 (`run_eval.py rescore`; the skill was not called again). The run itself was made with harness 1.0.0. Every row field and
> every aggregate that existed in 1.0 came out **identical** (checked: 0 of 288 rows and 0 aggregate values differ; the 1.0 files are kept
> as `results.harness-1.0.json` in the run folder). Added in 1.1: absolute W, D and H errors in percent, gate precision, flags on defective
> input, cuts by the number of fitted points and by cropped pictures, and a new outlier-recall definition. Because the baseline names no
> outlier, its recall is `-` under the old and the new definition alike. See `README.md` ("Harness versions").

* **Skill measured:** the frozen copy of `booth-image-to-model/` at commit `b377476` (skill version 2.8.0-rc1), code fingerprint
  `117671dca65f2c48` (the `.py` and `.json` files of `scripts/` and `schemas/`). Recreate the copy with
  `git archive b377476 booth-image-to-model | tar -x -C output/_eval/baseline`
  (the folder `output/_eval/baseline/` also holds a `COMMIT.txt` with the commit; both are git-ignored).
* **Harness version:** 1.0.0 for the run, 1.1.0 for the scoring. **Suite:** `oracle-v1`, seed 20261019: 32 scenes (8 per booth type) x 9
  perturbations = 288 runs. Suite fingerprint (sha256 of `suite.json`, which hashes every `case.json` and `scene.json`)
  `e29d9cff4dbf9908fe5a7af5f6a0b542ef9775ea698c5209b10a82c4c9e350e4`, pinned by a test (`test_the_baseline_suite_is_pinned`).
* **Exact command:**

```
python tools/eval/run_eval.py oracle --skill-dir output/_eval/baseline/booth-image-to-model --suite oracle-v1 --seed 20261019 --out output/_eval/runs/baseline-oracle-v1 --jobs 4
```

* **Cost:** 1309 s wall (22 min) for 288 runs with `--jobs 4`, each run being `box_fit.py` and `boothctl compile` (each fits the
  camera with 40 seeds). Machine: Windows 10, a 4-core laptop CPU, Python 3.12.3, numpy 1.26.4; other programs were running,
  so seconds are indicative. Compare versions by running both at the same time with the same `--jobs`.
* **Reproducibility:** the stored raw outputs were scored again with the final metrics code (`run_eval.py rescore`) twice, with harness 1.0 and
  with 1.1; every old row and every old aggregate came out identical, which also confirms that regenerating the suite from the seed gives the
  same truth. A fresh run of the same skill on the same suite (round 1 and round 2 of I1) reproduced the accuracy, flag and status fields of
  all 288 rows. The compile-only re-run of the frozen baseline that serves as side A in `RESULTS-I1b-arms.md` and `RESULTS-I1c.md` was checked the same way: 0 differences in
  2,880 values (corner error, field-of-view error, both ln proportion errors, the flag, the fit and compile statuses and the fitted W, D and H of all 288 runs); only its seconds differ, because of the machine load.

Everything below is about **synthetic scenes with a perfect pinhole camera**: read `README.md` ("What a synthetic set cannot show") first. The
absolute values are optimistic for real pictures; the use of this file is the comparison with later versions.

## What the baseline shows

* **Exact and lightly noisy corners are recovered very well.** With exact corners the median corner error is 0.00% of the image diagonal
  and both proportions are exact. At 1 px of noise it is 0.07%, the camera is 0.18 degrees off, W/H and D/H are off by
  0.00207 and 0.00257 in absolute ln, and a part stands 0.0285 m from its true place (medians). The absolute W, D and H errors at 1 px are
  0.06%, 0.14% and 0.09% (medians).
* **One displaced corner costs accuracy.** With a single 30 px outlier the median corner error is 0.41% (about six times that of 1 px noise),
  the rotation error 0.89 degrees, W/H 0.0166, D/H 0.0237, parts 0.0933 m: every corner is fitted
  with a squared loss. With two outliers of 15 to 60 px the corner error is 0.76%.
* **The flag is a fit-status test, not a test against held-out corners.** The status comes from an rms limit of 4 px and a solution-spread check. It flags 32 of 32 runs with a 30 px outlier and
  32 of 32 runs with swapped labels, but also 7 of 32 runs with 3 px noise whose fits are good, and 1 of 32 runs with
  exact corners. Over all runs it flags 56.9%; 98.6% of the really bad runs are flagged (recall), 42.7% of the flagged runs are really bad
  (precision), 43.3% of the good runs are flagged, and valid
  input (no injected error, right dimensions) is flagged in 8.59% of the runs. Agreement with the outcome-based truth label is 67.0%; it is low
  mostly because runs with an injected outlier are flagged although the fit they give is still good. Against input defects (an injected bad
  corner or three guessed dimensions) the flag has recall 95.6% and precision 93.3%.
* **Cropped pictures are harder for it, too.** The 11 scenes whose picture is a crop (principal point off centre; the skill fits a centred
  camera) have a median corner error of 0.41% against 0.27% for full-frame scenes, and valid input is flagged in 20.5% of the cropped runs against 2.38% of the full-frame ones.
* **It cannot say which corner is wrong.** No outlier is named. The worst-fitting point is an injected bad corner in 89.1% of the runs that have one:
  the signal a leave-one-out check has to match.
* **Assuming all of W/D/H costs proportion.** With all three stated as assumed values (about 12 % off, rounded to 0.5 m) the median corner error is 1.30%,
  the camera is 4.49 degrees off, D/H is off by 0.182 and a part 0.305 m from its place; 96.9% of these runs are flagged. This error is set by the
  harness constant `GUESS_LOG_SIGMA` and holds for any engine (see "Harness properties" below), so it is not a target for a skill change.
  (If the three assumed values happen to be right, `all_exact`, the fit is as good as it gets: 0.03%.)
* **No independent check exists.** The baseline ignores a per-point `fit` flag, so the two check corners of each scene are fitted like the rest and nothing
  holds back a point to test the fit.
* **`box_fit.py` prints more than one thing.** Its stdout is a summary line, a camera line and `WARNING:` / `HINT:` text lines, never one JSON object
  (0.00% of the runs). The fit inside `compile` and the standalone fit agree in 100.0% of the runs.
* **Time.** Median 6.99 s for `box_fit.py` alone and 8.00 s for `compile` (mean 9.48 s; swapped labels are the slowest, about 16.81 s). By booth type the medians are close, with peninsulas best and corner booths worst.

## What a better version has to show

These are the acceptance criteria of I1 as revised after round 1 (see `RESULTS-I1.md` and `RESULTS-I1b-arms.md`). Withholding two corners as
mandatory check corners costs fitted points and raised the false flags, so the independent check is leave-one-out with a robust loss and outlier
dropping, and a held-out `fit: false` corner is an optional feature.

| # | Claim to check | Where it is measured here | Baseline |
| --- | --- | --- | --- |
| 1 | With one 30 px outlier on a **fitted** corner and 8 or more fitted points, leave-one-out names at least 90 % of the injected corners, and camera and ratio errors are not worse (better is the aim) | `outlier_30`: "Injected corners that were fitted and that the skill names" (cut by fitted points), corner error, rotation, W/H, D/H, parts | nothing named; 0.41%, 0.89 deg, 0.0166, 0.0237, 0.0933 m |
| 2 | Clean and noisy (1 to 3 px) input: accuracy not worse (the paired 95 % interval of the difference is not clearly worse) | `clean`, `noise_1`, `noise_3`, every accuracy metric (no `-` marks in `compare_results.py`) | corner error 0.00%, 0.07%, 0.19% |
| 3 | Valid input flagged for review: at most the baseline plus 5 percentage points | "Runs with valid input ... that are flagged" | 8.59% (so at most 13.6%) |
| 4 | Really bad runs flagged: recall not lower than the baseline | "Really bad runs that are flagged" | 98.6% |
| 5 | `box_fit.py` prints one JSON object (a contract check, not an accuracy claim) | contract layer | 0.00% |
| 6 | Not slower | runtime layer | 8.00 s median for compile |

The verdict on rows 1 to 4 is in `RESULTS-I1c.md`: 1, 2 and 4 are met and 3 is missed by 0.5 point (14.1% against a limit of 13.6%), a limitation the
owner accepted when I1 was closed. Row 5 is met. Row 6 is not shown: no timing under comparable conditions exists.

Also look at gate precision (42.7% here), the flag rate on cropped pictures, the absolute dimension errors, and the flag rate on runs with a wrong
assumed dimension (`wrong_anchor_*` perturbations; the baseline cannot see those, see "Harness properties").

## Harness properties (not results about the skill)

* **Guessed against stated dimensions.** The `all_guess` error (D/H 0.182 against 0.0026 at 1 px with one stated dimension) comes from the
  constant `GUESS_LOG_SIGMA` in `perturb.py` (a 12 % error on each dimension, rounded to 0.5 m); because the guesses fix all three dimensions,
  the proportions inherit it, for any engine. The baseline engine gains exactly as much from one exact dimension as a changed engine does. It
  therefore shows the cost of the reader's habit of assuming everything, and it is not something a change to the fit can claim. The reader's prompt
  is outside this harness's oracle mode; only replayed or live reader replies can test it.
* **A wrong stated dimension is invisible to the ratios.** With one dimension stated wrongly, the corners still fix W/H and D/H, so the
  scale-free metrics stay near perfect while W, D and H are all off by about the stated error. This is what the reader's real failure looks like
  once it is asked to assume one dimension only. It is measured with the `wrong_anchor_*` perturbations and the absolute W, D, H errors in percent.
* **Cropped scenes** (11 of 32) carry a model mismatch on purpose; headline medians mix them with full-frame scenes.

Compare a new run with this one like this (same suite and seed):

```
python tools/eval/run_eval.py oracle --skill-dir booth-image-to-model --suite oracle-v1 --seed 20261019 --out output/_eval/runs/new --jobs 4
python tools/eval/compare_results.py --a output/_eval/runs/baseline-oracle-v1 --b output/_eval/runs/new --out output/_eval/compare.md
```

## Reading these numbers

- Intervals resample whole scenes (the rows of one scene are not independent).
- A metric that a skill version does not produce (for example outlier names in a version without leave-one-out) shows `-`.
- Outlier recall (harness 1.1) counts only injected corners that were fitted in that run: a corner held out as a check corner cannot be named by leave-one-out. Those runs are reported apart (flagged / check_failed). The harness 1.0 definition is the column "all injected" in results.json (`outlier_recall_all_injected`).
- Absolute W, D and H errors are what a wrong stated dimension looks like: the ratios stay right and all three metres are off by about the same share.
- "Really bad" is the harness convention in `tools/eval/metrics.py`: corner error above 1.5 % of the image diagonal, or W/H or D/H off by more than 0.10 in absolute ln. The flag is the quality gate of newer skills, or the box_fit status of older ones.
- Seconds are wall time of the two command-line calls, including interpreter and import start-up, on the machine that ran them.
- Synthetic scenes use a perfect pinhole camera and our own building blocks; see `tools/eval/README.md` for what that cannot show.
